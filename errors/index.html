Errors

Errors come in two formats, depending on where the request was rejected.

Gateway errors (authentication, rate limits, and quotas) have a status code and a message:

{
  "statusCode": 401,
  "message": "Access denied due to missing subscription key. Make sure to include subscription key when making requests to an API."
}

API errors also have a code and a request_id:

{
  "error": true,
  "httpcode": 422,
  "code": "geocoding_failed",
  "message": "The address could not be located.",
  "request_id": "12345678-abcd-4321-0000-1234abcd5678"
}

Handle errors by HTTP status first, then by code when there is one. Don't parse message, which may change.

Error reference​

StatuscodeCauseWhat to do

403Quota used upWait for the reset, or contact us
422invalid_coordinateslat or lon isn't a number, or is out of rangeFix the coordinates
422geocoding_failedThe address couldn't be locatedCheck the address, or send coordinates
422outside_atlasWe don't cover this locationCheck that lat and lon aren't swapped, and check coverage
429Rate limit exceededWait for Retry-After, then retry
500Something went wrong on our sideRetry later, and contact us if it continues. Don't assume the body is JSON

Retrying a 400, 401, 403, or 422 without changing the request will fail again.

Request IDs​

API errors and successful responses include a request_id, also sent in the X-LandUseLabs-Request-ID header. Include it when you contact us. Gateway errors don't have one, so include the time of the request instead.
